### Design decisions worth remembering
- **TokenHub reuses the OpenAI-compatible transport.** `TencentTokenHubProvider`
  subclasses `OpenAiCompatibleProvider` and only sets the provider label + default base
  URL. No duplicated HTTP logic. Registry maps `AGENT_PROVIDER=tencent_tokenhub` to it.

- **`client_factory` injection on the provider** is what keeps tests offline. Automated

  like "reported zero".
- **`ProviderErrorCode`** normalises 401/403/404/429/5xx/timeout/network/malformed/empty

- **`malformed_output`** distinguishes "model answered but unusable" from "model never
  reached" — the distinction Stage 4C needs.
- **Upstream error bodies are never surfaced** (a gateway body can echo request headers).

## LOCAL OLLAMA — WORKING (qwen3:8b, GPU-resident)

### The one thing to remember: Ollama's default context is 4096
Ollama gives **every** model a 4096-token context by default
(`OLLAMA_CONTEXT_LENGTH`, "4k/32k/256k based on VRAM" — with 8 GB VRAM it picks the
smallest tier). The advocate prompt alone is **~3968 tokens** (system 2326 + user 1641),
and Ollama splits the window roughly 50/50 between prompt and generation. So at 4096 the
prompt is **silently halved** and there is no room for the answer.

Symptom: `OUTPUT_TRUNCATED` (or `MALFORMED_JSON` before the truncation fix), with token
counts that add up to exactly 4095. Raising `AGENT_MAX_TOKENS` does NOT help — the
context window is the ceiling, and `num_ctx` in the OpenAI-compatible request body is
**ignored** by Ollama.

Two fixes, both outside RydeResolve code:
1. `OLLAMA_CONTEXT_LENGTH=16384` + restart Ollama, then use the plain model name.
2. Derive a variant with the context baked in (no restart, shares blobs, reversible):
   `FROM qwen3:8b` / `PARAMETER num_ctx 16384` / `ollama create qwen3-ctx16k -f Modelfile`
Used option 2 → `qwen3-ctx16k:latest`. Plain `qwen3:8b` is untouched. The temporary
`qwen3.8-ctx16k` derivative was removed with `ollama rm`.

### Model choice: size beats parameter count on this machine
RTX 4060 Laptop, **8 GB VRAM**. `qwen3.8:27b` is 18 GB → Ollama runs it **75% on CPU**
at ~5 tok/s (one advocate call ≈ 6 min). `qwen3:8b` is 5.2 GB → **100% GPU**, much
faster. The user switched to qwen3:8b mid-task; that was the right call.

### The clean reasoning knob (the one real code change)
Gemini 3.x Flash is a thinking model. Requesting lighter reasoning must not become a
first-class concept on the generic `LlmProvider` contract, so:
- `AgentCompletionRequest.extra_body: dict[str, object]` — a generic escape hatch.
- `_RESERVED_PAYLOAD_KEYS = {model, messages, temperature, response_format, max_tokens,

  config value could silently change which model answered, or what it was asked, while
  logs still showed the configured values.
- `AGENT_REASONING_EFFORT` (default unset) → `BaseAdvocateAgent._extra_body()` sends
  `{"reasoning_effort": ...}` **only when set**, so the default request body is unchanged.
- No chain-of-thought is requested or exposed anywhere.

### Reusable technique
To prove a test suite makes no outbound calls, inject a pytest plugin via `PYTHONPATH`
+ `-p <name>` that patches `socket.getaddrinfo`, `socket.socket.connect` and
`socket.create_connection` to raise for any non-loopback host — then **prove the guard
fires** on a real host, otherwise "it didn't trigger" is indistinguishable from "it's broken".
